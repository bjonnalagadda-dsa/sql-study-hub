5. Combining Tables: JOINs

Database: MyDatabase, then SalesDBScript: 05_JOINs.sql

Data is split across tables to avoid repetition. A JOIN stitches them back together using a matching column, usually a primary key to foreign key pair.

Remember this

  • INNER = overlap only. LEFT = all of left. FULL = all of both.
  • Anti join = LEFT JOIN + WHERE right_key IS NULL.
  • Alias tables (c, o) to keep column references short.

INNER JOIN

Keeps only rows that have a match in both tables.

SELECT c.id, c.first_name, o.order_id, o.sales
FROM customers AS c
INNER JOIN orders AS o
ON c.id = o.customer_id

LEFT JOIN

Keeps all rows from the left table, and matching rows from the right. Where there is no match the right columns are NULL. The most common join in analytics.

SELECT c.id, c.first_name, o.order_id, o.sales
FROM customers AS c
LEFT JOIN orders AS o
ON c.id = o.customer_id

RIGHT JOIN

Mirror image of LEFT JOIN. You can always get the same result by swapping the table order and using LEFT JOIN, which is why many people never use RIGHT.

SELECT c.id, c.first_name, o.order_id
FROM orders AS o
LEFT JOIN customers AS c      -- same as RIGHT JOIN with the tables swapped
ON c.id = o.customer_id

FULL JOIN

Keeps everything from both sides. Unmatched rows get NULLs on the other side.

SELECT c.id, c.first_name, o.order_id, o.customer_id
FROM customers AS c
FULL JOIN orders AS o
ON c.id = o.customer_id

Anti joins: find what is missing

Do a LEFT JOIN, then keep only rows where the right key IS NULL. That gives rows with no partner, such as customers who never ordered. The FULL anti join finds unmatched rows on either side.

-- customers with no orders
SELECT *
FROM customers AS c
LEFT JOIN orders AS o ON c.id = o.customer_id
WHERE o.customer_id IS NULL

-- unmatched on either side
SELECT *
FROM customers AS c
FULL JOIN orders AS o ON c.id = o.customer_id
WHERE o.customer_id IS NULL OR c.id IS NULL

CROSS JOIN

Every row of one table paired with every row of the other (a Cartesian product). 5 rows x 4 rows = 20 rows. Rarely what you want, but useful for generating combinations.

SELECT * FROM customers CROSS JOIN orders

Joining many tables

Start from the table that defines the question (usually the fact table, Orders) and LEFT JOIN each dimension onto it so no order is lost.

USE SalesDB
SELECT o.OrderID, o.Sales,
       c.FirstName AS CustomerFirstName,
       p.Product   AS ProductName, p.Price,
       e.FirstName AS EmployeeFirstName
FROM Sales.Orders AS o
LEFT JOIN Sales.Customers AS c ON o.CustomerID    = c.CustomerID
LEFT JOIN Sales.Products  AS p ON o.ProductID     = p.ProductID
LEFT JOIN Sales.Employees AS e ON o.SalesPersonID = e.EmployeeID

Common mistakes

  • Putting a filter on the right table in WHERE after a LEFT JOIN: it silently turns it into an INNER JOIN.
  • Joining on the wrong key and multiplying rows.
  • Forgetting that a CROSS JOIN has no ON clause and explodes row counts.

Check yourself

Which join lists customers that never placed an order?

LEFT JOIN customers to orders, then WHERE orders.customer_id IS NULL.

INNER vs LEFT JOIN?

INNER keeps only matched rows. LEFT keeps all left rows, filling right columns with NULL when unmatched.

How many rows does a CROSS JOIN of 5 and 4 rows return?

20.

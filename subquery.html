17. Subqueries

Database: SalesDBScript: 18_Subqueries.sql

A query inside another query. The inner result feeds the outer one. They can live in FROM, SELECT, JOIN or WHERE.

Remember this

  • Non-correlated runs once and is independent. Correlated runs per row and depends on the outer query.
  • EXISTS checks for presence, it does not care what is selected (SELECT 1 is convention).

Result types

Scalar: one value. Row/list: one column, many rows. Table: many rows and columns. The location decides which type is allowed (SELECT and comparison operators need scalar).

In FROM

The subquery acts as a temporary table. Great for filtering on a window result.

SELECT * FROM (
    SELECT ProductID, Price, AVG(Price) OVER () AS AvgPrice
    FROM Sales.Products
) AS t
WHERE Price > AvgPrice

In SELECT

Must return a single value, shown on every row.

SELECT ProductID, Product, Price,
       (SELECT COUNT(*) FROM Sales.Orders) AS TotalOrders
FROM Sales.Products

In JOIN

Pre-aggregate then join.

SELECT c.*, t.TotalSales
FROM Sales.Customers AS c
LEFT JOIN (
    SELECT CustomerID, SUM(Sales) AS TotalSales
    FROM Sales.Orders GROUP BY CustomerID
) AS t ON c.CustomerID = t.CustomerID

In WHERE: comparison, IN, ANY, ALL

Comparison operators need a scalar. IN checks a list. ANY is true if the comparison holds for at least one value, ALL if it holds for every value.

SELECT * FROM Sales.Orders
WHERE CustomerID IN (SELECT CustomerID FROM Sales.Customers WHERE Country = 'Germany');

SELECT EmployeeID, FirstName, Salary FROM Sales.Employees
WHERE Gender = 'F' AND Salary > ANY (SELECT Salary FROM Sales.Employees WHERE Gender = 'M')

Correlated subquery

References the outer row, so it re-runs for each outer row. Cannot run on its own. Readable but slow on large tables.

SELECT *,
       (SELECT COUNT(*) FROM Sales.Orders o
        WHERE o.CustomerID = c.CustomerID) AS TotalOrders
FROM Sales.Customers AS c

EXISTS

True if the subquery returns at least one row. It stops at the first match, so it is efficient. NOT EXISTS is the opposite.

SELECT * FROM Sales.Orders AS o
WHERE EXISTS (
    SELECT 1 FROM Sales.Customers AS c
    WHERE c.Country = 'Germany' AND o.CustomerID = c.CustomerID
)

Common mistakes

  • Returning more than one value where a scalar is required.
  • NOT IN with NULLs in the subquery result.
  • Using correlated subqueries on huge tables when a join or window would do.

Check yourself

Correlated vs non-correlated?

Correlated depends on the outer row and re-executes for each row; non-correlated runs once independently.

What does EXISTS return?

TRUE if the subquery yields at least one row.
